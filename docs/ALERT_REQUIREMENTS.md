# AtmoSync Alert Requirements

## 1. Objective

The purpose of the AtmoSync alert module is to monitor the
arbitrage recommendations generated by the existing data pipeline
and notify the operations team when a high-priority opportunity
or rerouting requirement is detected.

## 2. Source Dataset

**Database:** `telemetry_db`

**Table:** `fct_arbitrage_recommendation`

## 3. Alert Data

The alert module will use the following fields:

- `container_id`
- `telemetry_timestamp`
- `route`
- `temperature`
- `humidity`
- `vibration`
- `status`
- `distance_to_market_km`
- `spoilage_risk`
- `estimated_time_to_spoilage_hours`
- `recommended_action`
- `routing_recommendation`
- `arbitrage_priority`
- `reroute_required`

## 3.1 Sample Alert Data

Example record from `fct_arbitrage_recommendation`:

| Field | Value |
|---|---|
| Container ID | C003 |
| Route | Mumbai-Nashik |
| Temperature | 22.36°C |
| Humidity | 89.08% |
| Vibration | 0.25 |
| Status | normal |
| Distance to Market | 165 km |
| Spoilage Risk | high |
| Estimated Time to Spoilage | 12 hours |
| Recommended Action | monitor closely |
| Routing Recommendation | reroute recommended |
| Arbitrage Priority | high |
| Reroute Required | yes |

This record qualifies as a high-priority alert because the
arbitrage priority is high, rerouting is required, and the
routing recommendation indicates that rerouting is recommended.

## 4. High-Priority Alert Conditions

An alert should be generated when at least one of the following
conditions is true:

1. `arbitrage_priority = 'high'`

OR

2. `reroute_required = 1`

OR

3. `routing_recommendation = 'reroute recommended'`

## 5. Medium-Priority Condition

A record with:

`arbitrage_priority = 'medium'`

and:

`reroute_required = 0`

will be considered a monitoring condition and will not generate
an urgent alert in the initial implementation.

## 6. No Alert Condition

No notification should be generated when:

`arbitrage_priority = 'low'`

AND

`reroute_required = 0`

AND

`routing_recommendation = 'continue current route'`

## 7. Alert Information

Every generated alert should contain:

- Container ID
- Detection timestamp
- Current route
- Temperature
- Humidity
- Vibration
- Spoilage risk
- Estimated time to spoilage
- Recommended action
- Routing recommendation
- Arbitrage priority
- Reroute requirement

## 8. Notification Channels

The alert module will send notifications through:

- Slack
- Email

## 9. Duplicate Alert Prevention

The same opportunity should not generate repeated notifications
during every monitoring cycle.

A unique alert identifier will be used to prevent duplicate
notifications.

## 10. Invalid Data

Records with missing or invalid critical fields should not generate
an arbitrage alert.

Invalid records should be logged for investigation.

## 11. Responsibility

The existing data/dbt pipeline is responsible for calculating
arbitrage recommendations.

The Python alert module is responsible for:

1. Reading recommendations.
2. Validating the data.
3. Detecting alert conditions.
4. Preventing duplicate notifications.
5. Sending Slack notifications.
6. Sending email notifications.
7. Recording alert activity.
